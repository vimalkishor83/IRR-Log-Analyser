Help & FAQ

Everything you need to know about using the IRR Platform — for both admins and end users.

Who Can Do What

Admin
Full access — can sync data from ServiceNow, retrain the model, import CSV, manage users, and maintain the Knowledge Repository. Admins can see all pages regardless of module settings.
Analyst
Access is controlled by the modules an Admin assigns. By default, Analysts can use Log Analyzer and Recommendations. An Admin can also grant access to Knowledge for analysts who need to manage KB entries. If you can't see a page, ask your Admin to add that module to your account.

What Data Gets Synced from ServiceNow

The platform only pulls Resolved and Closed incidents. Open and In-Progress incidents are never stored — they are looked up live when you search by incident number.

Data Validation Rules Applied During Sync

Every record fetched from ServiceNow is checked against the rules below before it is saved. Records that fail any rule are counted as "skipped" — the sync summary in Admin shows how many failed and which rules fired most.

Incident Validation (6 rules)
# Rule What is checked Skipped if…
1 Required fields incident number, short_description, close_notes Any of these fields is empty or missing
2 Minimum length short_description length, close_notes length Description < 10 characters or resolution < 20 characters
3 Junk / placeholder text description and resolution content Text is a known throwaway phrase such as test, n/a, na, none, tbd, todo, done, fixed, closed, resolved, ok, yes, no, see above, see comments, as per call, as discussed, please see above, refer above, as per email
4 Duplicate resolution close_notes text vs. all existing resolutions in the DB The same resolution text already appears on 5 or more incidents (copy-paste template detected)
5 State verification state field value State is not Resolved or Closed (e.g. still Open or In Progress)
6 Assignment group filter assignment_group field vs. groups configured in Admin → ServiceNow Assignment Groups Groups are configured and this record's group is not in the active list. If no groups are added, all records pass.
KB Article Validation (3 rules)
# Rule What is checked Skipped if…
1 Minimum title length short_description / title field Title is empty or shorter than 10 characters
2 Junk / placeholder text title and resolution text Same junk phrase list as incidents above
3 Duplicate article title vs. existing KB articles in the DB An article with the same title already exists (prevents re-importing on every sync)
Tip for Admins: After a sync, check the Last Incident Sync message in Admin â†’ Index Status. It shows a breakdown like "skipped 120: 80 missing required field, 30 junk/placeholder text, 10 duplicate resolution" so you can identify and fix data quality issues in ServiceNow before the next sync.

Log Analyzer

What file types can I upload?
Supported: .log .txt .out .csv .gz. You can upload multiple files at once. Files are read in memory — nothing is saved to disk.
Does uploading a new log replace the old one?
Yes, but only your own previous analysis — each user's uploads replace just their own results, so two users analyzing logs at the same time won't overwrite each other.

Recommendations

How do I get a recommendation?
1 Enter an incident number (e.g. INC0001234) or paste an error message.
2 Click Get Recommendations.
3 Review the results — each card shows the resolution, confidence score, and source.
4 Click Helpful or Not Helpful to improve future results.
What if I enter an open or in-progress incident number?
The platform fetches the incident details live from ServiceNow, uses the description to search the local knowledge base, and shows you recommendations — even though the incident is not resolved yet. An amber banner will appear showing the live incident's state and details.
What does the confidence score mean?
It is a score from 0–99 combining text similarity, how many times the resolution has been used successfully, and overall user feedback. Higher = more likely to be relevant.
Why are there no results?
Either the knowledge base is empty (ask your Admin to sync or import data) or the error text is too different from anything stored. Try rephrasing — use the actual error code or exception class name for better results.

Admin Panel

When should I click Sync Now vs Retrain?
Sync Now — pulls fresh data from ServiceNow and then retrains automatically. Use this when new incidents have been resolved in ServiceNow.

Retrain — rebuilds the search index from data already in the local DB without calling ServiceNow. Use this after manually adding Knowledge entries or importing a CSV.
How do I bulk-import incidents from a CSV?
1 Click Download Template to get a CSV with all required columns and two example rows.
2 Fill in your incidents — one per row.
3 Choose the file and click Upload & Import.
4 The index is rebuilt automatically after import.
Required columns: incident_number, error_description, resolution. All others are optional but recommended.
How do I control what a user can see?
Go to Admin â†’ Manage Users. Each user has a role (Admin or Analyst) and a set of allowed modules. Tick the modules the user should be able to access. Admin users always have full access regardless of module settings.
What is the Knowledge Repository?
A manually maintained list of error patterns and their proven resolutions. These are searched alongside synced incidents. Use it to add fixes that are not in ServiceNow — e.g. known infrastructure quirks, config errors, or environment-specific issues. After adding entries, click Retrain in Admin to include them in searches.
How do I manage which ServiceNow groups are synced?
Go to Admin → ServiceNow Assignment Groups. You can add any ServiceNow assignment group name (e.g. Application Support, DBA Team) and toggle each one active or inactive. Only incidents belonging to an active group will be pulled during sync. If the list is empty, all resolved/closed incidents are synced regardless of group.

After changing the group list, click Sync Now to pull a fresh filtered dataset.
How is the sync scheduled automatically?
The background scheduler runs every SYNC_INTERVAL_HOURS hours (default 24, set in .env). It pulls incidents and KB articles automatically. You can also trigger it manually anytime from Admin â†’ Sync Now.
